# Подходы к реализации движения дронов в режиме RC-управления

## Введение

В данной работе реализована система управления роем дронов с использованием MAVLink-команд `RC_OVERRIDE`. Основная задача - обеспечить точное управление дронами через имитацию сигналов радиоуправления, что позволяет использовать низкоуровневое управление полётом без необходимости использования высокоуровневых команд навигации.

## 1. Архитектура системы управления

### 1.1. Режимы полёта ArduPilot

Система использует два основных режима полёта ArduPilot:

- **ALT_HOLD (режим 2)**: Дрон поддерживает заданную высоту, но не стабилизирует горизонтальную позицию. Требует активного управления по каналам roll и pitch для движения.
- **POS_HOLD (режим 16)**: Дрон автоматически стабилизирует как высоту, так и горизонтальную позицию. Встроенный PID-регулятор ArduPilot компенсирует внешние возмущения.

### 1.2. RC_OVERRIDE команды

`RC_OVERRIDE` позволяет программно переопределять значения RC-каналов:
- **Канал 1 (Roll/Aileron)**: Управление креном (влево-вправо)
- **Канал 2 (Pitch/Elevator)**: Управление тангажем (вперёд-назад)
- **Канал 3 (Throttle)**: Управление тягой
- **Канал 4 (Yaw/Rudder)**: Управление рысканием

Диапазон значений: 1000-2000, нейтральное значение: 1500.

## 2. Проблемы и решения

### 2.1. Проблема истечения RC_OVERRIDE_TIME

**Проблема**: ArduPilot имеет параметр `RC_OVERRIDE_TIME` (по умолчанию 3 секунды), после истечения которого дрон переходит в режим безопасности, если не получает новых команд.

**Решение**: Реализован механизм "keepalive" - отдельный поток, который непрерывно отправляет последние актуальные значения RC-каналов каждые 200мс. Это предотвращает истечение таймаута и не конфликтует с активным управлением.

```python
def start_rc_keepalive(self):
    """Отправка последних актуальных значений RC-каналов для поддержания связи."""
    def keepalive_loop():
        while True:
            with self.rc_channels_lock:
                roll = self.last_rc_channels['roll']
                pitch = self.last_rc_channels['pitch']
                # ... отправка команд
            time.sleep(0.2)
```

### 2.2. Проблема накопления ошибки и дрейфа

**Проблема**: При использовании только пропорционального (П) регулятора дроны накапливают систематические ошибки:
- Дрейф по оси roll при движении вперёд-назад
- Недостаточное торможение при приближении к цели
- Накопление ошибки позиционирования

**Решение**: Реализован PID-регулятор с интегральной составляющей:

```python
class PIDRegulator:
    def update(self, error, dt=None):
        # Пропорциональная составляющая
        p_term = self.kp * error
        
        # Интегральная составляющая с anti-windup
        self.integral += error * dt
        self.integral = max(-self.integral_limit, 
                           min(self.integral_limit, self.integral))
        i_term = self.ki * self.integral
        
        # Дифференциальная составляющая
        d_term = self.kd * derivative
        
        return p_term + i_term + d_term
```

**Преимущества PID-регулятора**:
- **Интегральная составляющая (I)**: Компенсирует систематические ошибки и дрейф
- **Anti-windup механизм**: Предотвращает переполнение интегральной составляющей
- **Автоматический сброс**: Интегральная составляющая сбрасывается при смене режима движения

## 3. Реализация управления движением

### 3.1. Движение по квадрату (одиночный дрон)

**Подход**: Последовательное выполнение команд движения в четырёх направлениях с торможением после каждого сегмента.

**Алгоритм**:
1. Отправка команды движения (например, `pitch=1700` для движения вперёд)
2. Ожидание заданной длительности
3. Переход в режим торможения с использованием П-регулятора на основе скорости
4. Остановка при достижении порога скорости

**Особенности**:
- В режиме **ALT_HOLD**: Требуется активное торможение через П-регулятор
- В режиме **POS_HOLD**: Встроенный PID-регулятор ArduPilot обеспечивает автоматическое торможение

### 3.2. Режим преследования (два дрона)

**Архитектура**: Децентрализованная система с обменом координатами между дронами.

#### 3.2.1. Обмен координатами

Каждый дрон:
1. Получает свою позицию через `LOCAL_POSITION_NED` сообщения MAVLink
2. Распространяет свою позицию другим дронам через общий словарь
3. Использует позиции других дронов для вычисления относительных координат

```python
def coordinate_exchange_loop(controllers):
    """Цикл обмена координатами между дронами."""
    while True:
        positions = {}
        for controller in controllers:
            positions[controller.config['id']] = controller.get_my_position()
        
        for controller in controllers:
            for drone_id, position in positions.items():
                if drone_id != controller.config['id']:
                    controller.update_other_drone_position(drone_id, position)
```

#### 3.2.2. Управление лидером

Лидер выполняет паттерн движения "вперёд-назад" с PID-торможением:
- Движение вперёд: `pitch=1700` (5 секунд)
- Торможение с PID-регулятором до остановки
- Движение назад: `pitch=1300` (5 секунд)
- Торможение с PID-регулятором до остановки

**PID-регулятор для торможения**:
- Использует ошибку скорости (целевая скорость = 0)
- Компенсирует дрейф по roll через интегральную составляющую
- Параметры: `kp=100.0`, `ki=50.0` (для roll), `ki=0.0` (для pitch)

#### 3.2.3. Управление преследователем

**Режим движения к цели**:
- Вычисляет относительную позицию до цели: `error_x = target_x - my_x`
- Применяет смещение на 2 метра вправо для избежания столкновения
- Использует PID-регулятор на основе позиционной ошибки

**Режим торможения**:
- Активируется при приближении к цели (`distance < threshold`)
- Использует PID-регулятор на основе скорости для плавной остановки

**Эволюция алгоритма**:

1. **Версия 1: Только П-регулятор**
   - Проблема: Недостаточное торможение, накопление ошибки
   - Решение: Добавлен PID-регулятор для торможения

2. **Версия 2: PID для торможения, П для движения**
   - Проблема: Преследователь не успевал нормально затормозить
   - Решение: Добавлен PID-регулятор для движения к цели

3. **Версия 3: Полный PID-контроль**
   - PID-регулятор для движения к цели: `kp=100.0`, `ki=10.0`
   - PID-регулятор для торможения: `kp=100.0`, `ki=50.0`
   - Результат: Плавное движение и точное торможение

## 4. Система координат и преобразования

### 4.1. NED система координат

MAVLink использует систему координат NED (North-East-Down):
- **X**: Север (positive north)
- **Y**: Восток (positive east)
- **Z**: Вниз (positive down)

### 4.2. Преобразование координат Webots → NED

В Webots ось X направлена в направлении кормы дрона, что требует инверсии:

```python
# В CoordsMonitor
self.position_ned['x'] = -msg.x  # Инверсия для соответствия NED
self.position_ned['y'] = -msg.y
self.position_ned['z'] = msg.z
```

### 4.3. Логика направления движения

**Важное открытие**: Направление RC-каналов в ArduPilot:
- `pitch > 1500` (например, 1700) = движение вперёд (на север)
- `pitch < 1500` (например, 1300) = движение назад (на юг)
- `roll > 1500` = движение вправо (на восток)
- `roll < 1500` = движение влево (на запад)

Это было критично для исправления проблемы, когда преследователь летел в противоположном направлении.

## 5. Оптимизация параметров PID-регуляторов

### 5.1. Параметры для торможения

- **kp=100.0**: Пропорциональный коэффициент обеспечивает быструю реакцию на ошибку скорости
- **ki=50.0** (для roll): Интегральный коэффициент компенсирует дрейф по roll
- **ki=0.0** (для pitch): Интегральная составляющая не требуется для движения вперёд-назад
- **integral_limit=200.0**: Ограничение интегральной составляющей (anti-windup)

### 5.2. Параметры для движения к цели

- **kp=100.0**: Пропорциональный коэффициент для движения к цели
- **ki=10.0**: Меньший интегральный коэффициент для плавного движения
- **output_limit=200.0**: Ограничение выходного сигнала для предотвращения резких движений

## 6. Результаты и выводы

### 6.1. Преимущества PID-регулятора

1. **Компенсация дрейфа**: Интегральная составляющая устраняет накопление ошибки
2. **Плавное торможение**: Более точная остановка по сравнению с П-регулятором
3. **Стабильность**: Меньше колебаний и перерегулирования

### 6.2. Сравнение подходов

| Характеристика | П-регулятор | PID-регулятор |
|----------------|-------------|---------------|
| Точность торможения | Средняя | Высокая |
| Компенсация дрейфа | Нет | Да |
| Сложность реализации | Низкая | Средняя |
| Время стабилизации | Длительное | Короткое |

### 6.3. Рекомендации

1. **Для точного позиционирования**: Использовать PID-регулятор с правильно настроенными коэффициентами
2. **Для режима ALT_HOLD**: Обязательно использовать активное торможение
3. **Для режима POS_HOLD**: Можно использовать только П-регулятор, так как встроенный PID ArduPilot компенсирует ошибки
4. **Для роевых алгоритмов**: Децентрализованный обмен координатами обеспечивает масштабируемость

## 7. Заключение

Реализованная система демонстрирует эффективность использования PID-регуляторов для управления дронами через RC_OVERRIDE команды. Интегральная составляющая критически важна для компенсации систематических ошибок и обеспечения точного позиционирования в режиме ALT_HOLD.

Система успешно решает задачи:
- Точного движения по заданным траекториям
- Плавного торможения без перерегулирования
- Компенсации дрейфа и накопления ошибки
- Децентрализованного управления роем дронов
