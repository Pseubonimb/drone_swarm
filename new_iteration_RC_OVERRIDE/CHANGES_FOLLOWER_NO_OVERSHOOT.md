# Изменения: преследователь больше не перелетает лидера

Краткое описание всех доработок, благодаря которым дрон-преследователь стабильно следует за лидером без перелёта и без отставания по оси X.

---

## 1. Проблема

Наблюдались два типа неустойчивого поведения:

- **Перелёт (overshoot):** преследователь по инерции пролетал мимо лидера при сближении.
- **Отставание по X:** преследователь не догонял лидера по оси North (X), ошибка по X росла (до десятков метров), при этом перелётов не было — преследователь летел медленнее лидера.

Причины: слабый отклик по pitch при большой ошибке (малый Kp), отсутствие демпфирования при сближении (Kd=0), несоответствие частоты контура управления и частоты обновления позиции, редкая выдача позиции с автопилота.

---

## 2. Изменения в регуляторе преследователя (PID)

- **Увеличение Kp (с 1 до 8 по умолчанию).** При Kp=1 при ошибке по X ~50 м выход P-канала был ~50, что давало слабый наклон вперёд (pitch далёк от 1300) и постоянное отставание. При Kp=8 преследователь при большой ошибке выходит на достаточный наклон вперёд и догоняет лидера. Параметр: `--kp` (по умолчанию 8.0).

- **Введение Kd = 10 по умолчанию.** Дифференциальная составляющая даёт демпфирование при сближении с целью и уменьшает перелёты. Параметр: `--kd` (по умолчанию 10.0).

- **Сглаживание D-члена (derivative_alpha=0.7).** В PIDRegulator добавлен экспоненциальный фильтр по производной ошибки, чтобы Kd не давал всплесков из-за шума измерений.

- **Ограничение выхода и anti-windup.** Выход PID ограничен (output_limit=200 по каналу roll/pitch), интегральная составляющая ограничена (integral_limit), чтобы не было накопления интеграла и рывков при насыщении.

---

## 3. Синхронизация контура с данными

- **Ограничение частоты контура 50 Hz.** Цикл преследования ограничен периодом 0.02 с (50 Гц), чтобы частота управления не превышала частоту обновления позиции. Параметр: `--control-hz 50` (по умолчанию 50; при `--control-hz 0` ограничение отключается).

- **Фиксированный dt в PID.** При включённом rate limit в вызов `update()` регулятора передаётся фиксированный шаг dt=0.02 с, чтобы интеграл и производная считались стабильно, без джиттера из-за переменного периода цикла.

- **Запрос частой выдачи позиции.** При инициализации каждого дрона отправляется MAVLink-команда SET_MESSAGE_INTERVAL для LOCAL_POSITION_NED с интервалом 20 000 мкс (50 Гц), чтобы автопилот отдавал позицию с предсказуемой частотой, а не 1–4 Гц по умолчанию.

---

## 4. Логирование

В CSV-лог записываются: время t, позиции лидера и преследователя (leader_x, leader_y, follower_x, follower_y), ошибки по осям (error_x, error_y), скорости преследователя (follower_vx, follower_vy), период цикла (loop_dt). Это позволяет анализировать перелёты, отставание и эффективную частоту контура (например, через `analyze_log.py`, `plot_log_coords.py`).

---

## 5. Параметры по умолчанию

| Параметр     | Значение | Описание |
|-------------|----------|----------|
| `--kp`      | 8.0      | P-коэффициент |
| `--ki`      | 0.0      | I-коэффициент |
| `--kd`      | 10.0     | D-коэффициент (демпфирование) |
| `--control-hz` | 50.0  | Частота контура преследования (Гц); 0 = без ограничения |

Сценарий по умолчанию: `leader_forward_one_move.py` в каталоге `experiment_stability` (запуск после старта симуляции или SITL).
